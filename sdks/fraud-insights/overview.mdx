Fraud Insights is Youverify's device and behavioural intelligence service. It runs quietly in the background of your web or mobile app, recognises the device behind each session, and checks it for signs of risk. It also records what happens during the session and other events you choose to send. Your users never see a screen, a prompt or a delay.

Everything it learns is tied to the entity, shown in the Youverify dashboard under **Signals**, and used to enrich the entity's [risk score](/concepts/risk-scoring) and profile information.

## Why use Fraud Insights

Identity checks tell you who someone claims to be. Fraud Insights tells you how they are actually connecting. That is where most fraud shows up first, because the person who passed onboarding is not always the person using the account later.

## What Fraud Insights looks at

The SDK collects signals passively. Each signal is shown on the session record, and several of them feed the device risk score.

<Tabs>
  <Tab title="Device fingerprint">
    A snapshot of the device and its environment at the time of the session:

    - **Environment checks:** virtual machine, bot activity, factory reset, and root access or jailbreak.
    - **Privacy and masking:** VPN, Tor network and incognito mode.
    - **Block list:** whether the device is already on your block list.
    - **Platform and location:** platform, IP address, time zone and geolocation.
    - **Familiarity:** whether the IP address is new, plus when the device was first and last seen.
  </Tab>
  <Tab title="Threat indicators">
    Patterns across sessions that a single check cannot show:

    - **IP velocity:** how many unique IP addresses appear in the current session, the last hour, the last 24 hours and the last 7 days.
    - **Device and entity relationship:** how many entities use the same device, how many devices belong to the same entity, and whether this is a new device for the entity.
    - **Location velocity:** whether the IP address and the geolocation disagree.
    - **Location pattern anomaly:** how many cities appear in a session, and whether the entity looks like it is moving unusually.
    - **IP change timeline:** each IP address seen in the session, with a note when it returns to the original.
  </Tab>
  <Tab title="Session events">
    A timeline of what happened in the session:

    - Automatic `session_start` and `session_end` events.
    - Custom events you send, such as page views, a checkout started or a withdrawal requested, each with optional metadata.
    - Session duration, start and end times.
  </Tab>
</Tabs>

<Note>
  Signals are indicators, not proof of fraud. A single signal, such as a VPN, is rarely enough to act on alone. The value comes from combining signals, which the device risk score and the entity risk score do for you.
</Note>

## How it works

<Steps>
  <Step title="Add the SDK">
    Add the Fraud Insights SDK to your web or mobile app with your Public Merchant Key. See the [integration guide](/sdks/fraud-insights/web).
  </Step>
  <Step title="Start a session">
    When a user opens your app, the SDK starts a session, identifies the device and sends a `session_start` event. If you pass an entity ID, the session is linked to that entity.
  </Step>
  <Step title="Send events">
    Send meaningful events as the user moves through your product, for example a login, a page view or a payment step. Event names and metadata are yours to choose.
  </Step>
  <Step title="Review and act">
    Youverify analyses the signals and scores the device. You review the results in the dashboard, and they raise or lower the entity's risk score. High-risk sessions can be turned into a case for investigation.
  </Step>
</Steps>

## See the results in the dashboard

Open **Signals** and select **Behavioural Insights**. Each row is one session on one device, showing the entity, device ID, application name, device type and OS, event count, session duration, date and an anomaly flag. From here you can select sessions and create a case.

Open a session to see its full record:

- **Summary:** entity ID, signal ID, application name, signal source (for example, Web SDK), device risk score out of 100, fraud alert status, and session start, end and duration.
- **Device fingerprint:** the environment checks, privacy flags, IP address and location described above.
- **Threat indicator tab:** IP velocity, device and entity relationship, location checks and the IP change timeline.
- **Events tab:** every event in the session, with a preview of each one.

The same session data supports the other tabs in **Signals**: Activities, Events, Alerts and Cases.

## How it fits with the rest of Youverify

- **Risk scoring:** at onboarding the risk score reflects identity and AML data. Fraud Insights adds behavioural history over time, so the score gets more accurate as the entity uses your product. See [Risk scoring](/concepts/risk-scoring).
- **Continuous monitoring:** device and access patterns are part of the behavioural layer described in the [monitoring model](/concepts/monitoring-model).
- **Verification SDKs:** Fraud Insights adds no screens or prompts, so it runs alongside the [Anti-Deepfake Liveness](/sdks/liveness/overview) and [Document Capture](/sdks/document-capture/overview) SDKs.

<Info>
  Fraud Insights works on web and on mobile (Android and iOS). The session model, events and configuration are the same on every platform. Signals can differ slightly by platform, because browsers and mobile operating systems expose different information about the device.
</Info>

## Good practice

- **Combine signals.** Review several indicators together, and avoid blocking a customer on one signal unless it is clearly high risk, such as a known block-listed device.
- **Link sessions to entities.** Pass the entity ID on `get()`, `sendEvent()` and `close()` so device history builds up on the right customer.
- **Name events clearly.** Use consistent, descriptive names and add metadata, so patterns are easy to spot later.
- **Prefer extra checks over hard blocks.** For a medium-risk session, step up with liveness, email or phone verification rather than rejecting the customer outright.
- **Use the right key.** Use the sandbox setting and key while testing, and the production setting and key when you go live.
